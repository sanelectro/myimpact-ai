# M5.2 — Knowledge APIs

M5.2 exposes the existing M3 knowledge capabilities through the product-facing `/api/v1/knowledge` boundary.

## APIs

- `POST /api/v1/knowledge/documents` — upload and process a knowledge document
- `GET /api/v1/knowledge/documents?user_id=...` — list the user's documents
- `GET /api/v1/knowledge/documents/{document_id}?user_id=...` — get a document
- `POST /api/v1/knowledge/documents/{document_id}/reprocess?user_id=...` — reprocess a document
- `POST /api/v1/knowledge/retrieve` — semantic knowledge retrieval

## Boundary rules

- Reuse existing M3 services; do not duplicate document processing or retrieval logic.
- Do not expose storage paths, embedding vectors, embedding models, repository details, or similarity scores.
- Document reads and reprocessing enforce user ownership at the product API boundary.
- Retrieval continues to use semantic similarity only for discovery; it is not an impact score.
- No database schema or migration changes.
- Authentication is not implemented in M5.2. `user_id` is therefore an explicit temporary request context and can later be replaced by authenticated user context without changing the product routes.
