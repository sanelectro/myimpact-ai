# MyImpact — M6.6 Impact Analysis

## Milestone overview

**Milestone:** M6.6  
**Status:** Planned; acceptance criteria and implementation are not confirmed complete.

M6.6 delivers an evidence-grounded analysis of goal and milestone progress. It
explains how submitted work relates to sourced expectations, what evidence is
still needed, and which next contributions could address gaps. It does not
produce 1:1 briefs or career reports; those are M6.7.

## Scope

- Start with monthly analysis; consider quarterly and yearly views after the
  monthly model is validated.
- Compare employee goals against explicit expectations available from goals,
  role/company context, and managers. Preserve sources and flag missing or
  conflicting expectations instead of inventing them.
- Represent expectations as criteria with equal weights by default; define
  permissions and validation for any adjusted weights.
- Count only employee-submitted evidence accepted by the reporting manager.
  Rejected or unreviewed evidence does not contribute to scores.
- Let AI propose traceable evidence-to-criterion matches and partial progress,
  with source links and confidence. The employee confirms or corrects proposed
  partial progress before it affects scores.
- Use consistent evidence eligibility and scoring rules for goals and
  milestones.
- Explain scores, coverage, gaps, and uncertainty. Tie suggested next
  contributions to unmet criteria and distinguish suggestions from completed
  work.

## Access and trust boundaries

- Analysis is private to its owner by default.
- Reporting managers receive only the access needed to review and accept or
  reject their reports' submitted evidence. This does not grant access to
  private 1:1 notes or career reports.
- Distinguish AI suggestions, source facts, and user-authored content.
- Do not rewrite source evidence, goal state, or assessments when analysis is
  created or edited.
- Show when saved analysis is stale after its source goals or evidence change.

## Acceptance criteria

- [ ] Expectations and criteria show their sources; missing or conflicting
  expectations are visible.
- [ ] Default and adjusted criterion weights are validated and shown.
- [ ] Only employee-submitted, manager-accepted evidence contributes to goal
  and milestone scores.
- [ ] Manager review, rejection, resubmission, and audit behavior are defined
  and enforced by the API.
- [ ] AI-proposed evidence matches and partial progress include sources and
  confidence, and require employee confirmation or correction.
- [ ] Score calculations are consistent across goal, milestone, and dashboard
  surfaces; migration from the legacy M6.3 evidence-count model is defined.
- [ ] Monthly analysis explains progress, evidence coverage, gaps, and
  uncertainty without unsupported claims.
- [ ] Suggested contributions are clearly labeled and never treated as
  completed work.
- [ ] Empty, incomplete, stale, and out-of-period data are handled explicitly.
- [ ] Owner-scoped access protects analysis; manager access is limited to
  evidence review.
- [ ] API/service, UI, and end-to-end tests cover review, scoring, traceability,
  access boundaries, and insufficient-data behavior.

## Decisions to resolve before implementation

- Define evidence-review states, rejection reasons, resubmission, audit history,
  and notification behavior.
- Define how goal, role/company, and manager expectations are reconciled.
- Define adjusted-weight permissions and validation.
- Keep manager acceptance of evidence separate from employee confirmation of
  AI-proposed partial progress.
- Define how analysis is versioned and marked stale when source data changes.

## Definition of done

Goal and milestone analysis uses only the agreed, manager-accepted evidence and
weighted-criteria rules. Employees can inspect source-linked scores, coverage,
uncertainty, and gaps; confirm or correct AI proposals; and see next
contributions clearly distinguished from completed work. Access is correctly
scoped, unsupported claims are omitted or flagged, and backend/UI/end-to-end
tests cover the agreed workflow.
