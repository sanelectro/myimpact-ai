# M5.3 — Goal + Expectation APIs

M5.3 extends the product-facing `/api/v1` boundary with goal management and read-only document expectation access.

## APIs

### Goals
- `POST /api/v1/goals?user_id=...`
- `GET /api/v1/goals?user_id=...`
- `GET /api/v1/goals/{goal_id}?user_id=...`
- `PUT /api/v1/goals/{goal_id}?user_id=...`
- `DELETE /api/v1/goals/{goal_id}?user_id=...`

Goal responses intentionally omit `user_id`; the temporary `user_id` query parameter is only context until authentication is introduced.

### Expectations
- `GET /api/v1/knowledge/documents/{document_id}/expectations?user_id=...`

Expectations are currently persisted against documents, not goals. There is no persisted goal-to-expectation relationship in the M4 model, so M5.3 does not invent one. Goal relevance remains an application-level concern for the later impact APIs.

## Boundaries
- Reuses existing GoalService and DocumentExpectationRepository through application services.
- Enforces user isolation before returning or mutating goal/document data.
- No database schema changes.
- No authentication implementation.
- No changes to M3/M4 intelligence behavior.
