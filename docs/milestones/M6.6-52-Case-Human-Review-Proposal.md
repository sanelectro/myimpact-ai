## Important review limitations

- These assessments are based only on the case details and evidence text supplied in the JSON. URLs use `example.test` and are treated as illustrative; I did not verify external source contents.
- The labels below are proposed using each case's own `review_label_options`. Similar-looking labels across categories are not interchangeable.
- The JSON's `expected_result` is treated as a provisional reference, not as truth. Where the case is incomplete, internally inconsistent, or tests a process without supplying the necessary event/output, I flag it rather than manufacture a definitive reference.
- Several cases use synthetic evidence that merely repeats the scenario. These are useful as scenario descriptions but are weak ground truth unless concrete evidence payloads, paired outputs, measurements, or version data are added.
- This is one independent assessment pass. A qualified human reviewer/product owner must confirm the proposed labels and rationales before approving the benchmark.
