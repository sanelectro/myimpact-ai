# MyImpact — M6.8 End-to-End UX Validation and Release Readiness

## Milestone overview

**Milestone:** M6.8  
**Status:** Not confirmed complete.

M6.8 validates the integrated user journey and records whether the application is ready for release. It is the final release gate and must run after all committed M6 scope, including the later-added M6.9 Admin Portal and Platform Access work, is implemented and reconciled.

## Release acceptance checklist

- [ ] Fresh setup and database migrations work using documented instructions.
- [ ] Seed/demo data loads without enum, migration, or conflict errors.
- [ ] Full backend test suite passes.
- [ ] Frontend tests and production build pass.
- [ ] API contracts, base URL configuration, and CORS behavior are verified.
- [ ] Registration, login, refresh-token rotation, logout, and protected API access work with the configured authentication issuer.
- [ ] Organization creation/linking, profile updates, and reporting-manager constraints are validated at the API boundary.
- [ ] Organization-scoped goals remain associated with the correct company and private to their owner.
- [ ] Platform-admin privileges cannot be granted through public registration or ordinary user flows.
- [ ] Admin-only routes and APIs reject non-admin users and correctly enforce authorized cross-company access.
- [ ] Admin invitations, expiry/resend behavior, account disable/reactivation, and refresh-session revocation are validated.
- [ ] Current database migrations, including authentication credentials/sessions, milestone-evidence, organization/reporting, and platform-admin changes, apply cleanly to a fresh database.
- [ ] Manual goal creation and supported document import work end to end.
- [ ] Repeated and duplicate-import cases behave correctly.
- [ ] Goal lifecycle and assessment calculations are consistent.
- [ ] Evidence associations and source provenance are correct.
- [ ] Dashboard, goal list, and goal detail agree on status and progress.
- [ ] Loading, empty, error, and retry states are covered.
- [ ] Authentication and user-level data isolation are verified.
- [ ] Responsive layout and basic accessibility are reviewed.
- [ ] Diagnostics are useful and do not leak sensitive content.
- [ ] README/runbook and known limitations are current.
- [ ] Final regression results and release decision are recorded.

## Integrated journey

Validate the complete agreed product flow from registration and organization setup through goal entry/import, evidence capture, assessment, admin operations, insights, and career outputs where in scope. Include a no-data path, partial-data path, and representative authorization and failure/retry paths.

## Scope alignment

The numbered M6 delivery plan includes 1:1/report and AI assistant before this milestone, while the post-M6.3 data-first roadmap proposed deferring some analysis work. The expanded plan also includes authentication, organization/reporting-manager relationships, and M6.9 Admin Portal and Platform Access. Reconcile these differences and explicitly identify any deferred features before setting the final release scope.

## Completion rule

Do not mark M6 complete solely because individual milestone documents or historical test results exist. Record the current commit/environment, exact commands and scenarios run, results, and unresolved limitations.
