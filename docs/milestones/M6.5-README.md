# MyImpact — M6.5 Goal/Milestone Evidence

## Milestone overview

**Milestone:** M6.5  
**Status:** Validated against the current implementation on 24 October 2026; AI-generated goal criteria and evidence assessment are in M6.6, with Impact Analysis planned for M6.7.

M6.5 lets users add evidence either directly to a goal or specifically to one of that goal's milestones. The user chooses the destination when adding the evidence.

## User flow

1. Open a goal and add or select evidence describing a contribution or outcome.
2. Associate the evidence with the goal and optionally with a milestone that belongs to that goal.
3. Review the evidence and its source/provenance.
4. See the evidence listed with its chosen destination.

Evidence associated with a milestone remains associated with its parent goal. Evidence that is relevant to the overall goal but not a specific milestone can remain goal-level.

## Implementation and validation

- Evidence mappings can optionally identify a milestone while retaining the parent goal association.
- The API validates ownership and milestone-to-goal relationships; the database migration enforces the association.
- The M6.5 browser scenario verified both direct goal attachment and milestone attachment.
- Backend API/integration tests verified invalid associations, ownership, and milestone deletion behavior.
- All 22 current SQL migrations validated and applied to a fresh disposable PostgreSQL database; the existing local database was not changed.

The association schema change is versioned in `myimpact-db/migrations/V20261023142700__add_milestone_evidence_associations.sql`.

## Acceptance criteria

- A user can add evidence to a goal and inspect its title, description, source, capture date, and relevance.
- When adding evidence, the user can choose direct goal attachment or a milestone belonging to that same goal.
- Invalid, archived, or cross-goal milestone associations are rejected.
- Ownership checks protect goals, milestones, and evidence. Duplicate evidence and repeat submissions have clear behavior.
- The API returns the destination with each goal evidence item.
- The database prevents a milestone association from pointing to a milestone owned by a different goal.
- Deleting an archived milestone preserves its evidence as goal-level evidence rather than deleting the evidence.
- Goal-level evidence continues to work when no milestones exist.
- Backend API tests cover invalid associations, the integration test covers both destination choices and milestone deletion behavior, and Playwright covers both destination choices.
- The combined M6.1–M6.5 browser suite runs with `cd myimpact-web && npm run test:e2e:m61-m65`.

## Scope boundaries

- This milestone is limited to evidence storage, goal/milestone associations, APIs, and the user-facing choice to attach evidence.
- AI assessment and Impact Analysis are out of scope for M6.5. M6.6 adds criteria and evidence assessment to the Goals workflow; M6.7 adds a separate Impact Analysis experience. 1:1 preparation and career reports are M6.8. Adding evidence does not trigger AI assessment.
- A new external connector (for example Jira or GitHub synchronization) is not required for this flow; consider it separately if it becomes a product requirement.
- M6.5 does not alter lifecycle rules or infer milestone completion from evidence.
